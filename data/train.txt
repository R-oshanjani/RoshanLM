Python data structures are fundamental to machine learning programs because data must be represented in a form that algorithms can process. Lists are useful for ordered collections, dictionaries are useful for key value mappings, tuples can represent fixed collections, and sets can represent unique elements. Understanding the properties of each structure helps developers select an appropriate representation for an algorithm.

A list can contain values of different Python types. Elements can be accessed using zero based indexing. Negative indexing allows access from the end of a list. Slicing creates a portion of a list using a start index, stop index, and optional step. Lists support methods such as append, extend, insert, remove, pop, sort, and reverse.

Dictionary objects store relationships between keys and values. Keys must be hashable objects, while values can be objects of many different types. Dictionary lookup is generally efficient and dictionaries are frequently used for counting, grouping, configuration, and representing structured records.

List comprehensions provide a compact syntax for constructing lists. A comprehension can iterate over a collection and optionally apply a condition. Although comprehensions are concise, readable code should be preferred over unnecessarily complicated expressions.

Iterators provide a mechanism for processing elements one at a time. Generators are a convenient way to create iterators using the yield keyword. Generators can be useful when processing large datasets because they do not need to keep every result in memory simultaneously.

Python decorators allow a function or class to be wrapped with additional behavior. Decorators are commonly used for logging, authorization, caching, timing, and framework functionality. A decorator receives a function and returns another callable object.

Context managers manage resources that need to be acquired and released safely. The with statement is commonly used with files, locks, database connections, and other resources. Using context managers reduces the chance of leaving resources open after an operation finishes.

A Python file can be opened using the open function. Reading a file loads its contents into the program, while writing creates or replaces content. Appending adds content to an existing file. The with statement is commonly used so that the file is automatically closed.

Software testing checks whether a program behaves as expected. Unit tests verify small pieces of functionality. Integration tests verify interactions between components. End to end tests evaluate complete workflows. Automated testing can identify regressions when code changes.

Machine learning projects frequently begin with exploratory data analysis. Exploratory analysis examines the shape, columns, distributions, missing values, duplicate records, and relationships in a dataset. Visualization can reveal patterns that are difficult to notice from raw tables.

A histogram shows the distribution of a numerical variable. A scatter plot shows the relationship between two numerical variables. A box plot can reveal central tendency, spread, and possible outliers. Correlation matrices can summarize relationships between numerical variables.

Correlation measures the strength and direction of association between variables. A high correlation does not necessarily imply causation. Machine learning practitioners should distinguish statistical association from causal relationships.

Outliers are observations that differ substantially from the rest of a dataset. Outliers may represent genuine rare events, measurement errors, data entry errors, or unusual cases. Removing an outlier should only be done when there is a defensible reason.

Data preprocessing should be performed carefully to avoid information leakage. For example, calculating a scaling mean using both training and validation data allows information from the validation set to influence the training process. Preprocessing transformations should generally be fitted using training data and then applied to validation and test data.

A scikit-learn pipeline can combine preprocessing and model training steps. Pipelines make transformations reproducible and reduce the risk of accidentally applying different preprocessing operations during training and inference.

Grid search evaluates combinations of specified hyperparameters. Random search samples hyperparameter combinations from distributions. Hyperparameter optimization can improve model performance, but it should be performed using appropriate validation procedures.

Class imbalance occurs when some target categories contain substantially more examples than others. Accuracy may be misleading in this situation. Precision, recall, F1 score, balanced accuracy, class weights, resampling, and threshold adjustment can provide more informative approaches.

A binary classifier produces a score or probability for a positive class. Changing the classification threshold changes the balance between precision and recall. A lower threshold may identify more positive examples while also increasing false positives.

The receiver operating characteristic curve evaluates the relationship between true positive rate and false positive rate across thresholds. The area under the ROC curve provides a threshold independent summary, although precision recall analysis can be more informative for highly imbalanced problems.

Regression models can also be evaluated using R squared. R squared describes the proportion of variance explained by a model relative to a baseline, but it should not be interpreted as proof that a model is appropriate for a particular application.

Time series data requires special attention because observations are ordered in time. Randomly splitting a time series can allow future information to influence training. Time based validation should preserve the chronological relationship between training and evaluation data.

Feature engineering for time data can include year, month, day, hour, weekday, elapsed time, rolling averages, and lag features. These features can help models capture temporal patterns.

Natural language data has additional challenges because words can have multiple meanings and context can change interpretation. Modern language models address this by learning contextual representations in which the representation of a token can depend on surrounding tokens.

A word embedding maps a token to a vector. Traditional word embeddings often assign one vector to each word. Contextual Transformer representations can change depending on the tokens surrounding a word.

Token frequency is important for tokenizer design. Frequent patterns are useful candidates for BPE merges. Rare words can often be represented using several subword tokens. Subword tokenization provides a flexible vocabulary.

Special tokens can represent structural information such as beginning of sequence, end of sequence, padding, or unknown values. A tokenizer must define consistent behavior for special tokens if they are required by the model.

Sequence padding is used when examples in the same batch have different lengths. Padding tokens allow tensors to have a consistent shape. Attention masks can prevent the model from using padding positions as meaningful content.

The context window of a language model determines how much previous text can be processed at once. A context length of 32 means the model can consider at most 32 token positions in a single forward pass when using the current architecture.

Longer context windows increase the amount of computation performed by self attention. Standard self attention has computational complexity that grows approximately quadratically with sequence length. This is one reason efficient attention methods are an active research area.

Attention weights represent how strongly one position uses information from another position. The weights are produced by comparing queries and keys and applying softmax. The resulting weighted combination of values becomes the attention output.

A causal mask can be implemented using a lower triangular matrix. Positions on and below the diagonal remain visible, while positions above the diagonal are masked. This prevents information from future positions from entering the current prediction.

Softmax converts a vector of logits into nonnegative values that sum to one. In attention, softmax is applied to scaled attention scores. In classification, softmax can convert output logits into class probabilities.

Numerical stability is important when implementing softmax and cross entropy. Large positive or negative values can cause overflow or underflow if operations are implemented carelessly. Framework functions such as PyTorch cross entropy are designed to handle these calculations efficiently.

Layer normalization normalizes activations across the feature dimension. It is commonly used in Transformer architectures because it can stabilize training. Pre normalization places the normalization operation before attention and feed forward sublayers.

Residual connections allow a sublayer to modify an existing representation rather than reconstructing the complete representation from scratch. They can improve gradient flow through deep neural networks.

The Transformer feed forward layer applies a learned transformation independently at every token position. The same feed forward parameters are reused across positions, while attention allows information to move between positions.

The output vocabulary layer can be implemented as a linear transformation from the embedding dimension to the vocabulary size. If the vocabulary contains 200 tokens, each sequence position produces 200 output logits.

Weight tying is a technique in which the token embedding matrix and output language modeling matrix share parameters. Weight tying can reduce parameter count and sometimes improve language model performance.

Model initialization affects training. Neural network parameters are generally initialized using small random values according to initialization schemes designed to maintain reasonable activation and gradient scales.

Gradient descent attempts to find parameter values that minimize a loss function. The gradient indicates the direction in which the loss increases most rapidly. Moving in the opposite direction can reduce the loss.

Stochastic gradient descent estimates gradients using a batch rather than the entire dataset. Mini batch training provides a compromise between computational efficiency and gradient estimation quality.

AdamW combines adaptive gradient scaling with decoupled weight decay. It is frequently used for Transformer optimization because it works well across many neural network configurations.

Weight decay discourages excessively large parameter values. It is related to regularization and can help reduce overfitting. The appropriate value depends on the dataset and model architecture.

Early stopping monitors validation performance and stops training when improvement has stopped for a specified number of evaluations. Early stopping can reduce unnecessary training and help prevent overfitting.

A learning rate scheduler changes the learning rate during training. Common strategies include cosine decay, linear decay, step decay, and plateau based schedules. Scheduling can help the optimizer make larger updates early and smaller updates later.

Training curves provide useful diagnostic information. A graph of training and validation loss can show whether a model is learning, underfitting, overfitting, or becoming unstable.

If training and validation loss both decrease, the model is generally learning useful patterns. If training loss decreases while validation loss begins increasing, overfitting may be occurring. If both losses remain high, the model may need more training, better data, a different architecture, or different optimization settings.

Language model evaluation should use a held out corpus that represents the intended application. If the validation corpus contains only a narrow subset of the domain, the validation metric may not represent real world performance.

Qualitative evaluation is also useful. Prompts can be designed to test definitions, explanations, code concepts, comparisons, and domain terminology. Generated outputs should be examined for repetition, factual errors, incomplete sentences, and unsupported claims.

Repetition is a common failure mode in small language models. A model may repeatedly generate the same token or phrase because its learned probability distribution is poorly calibrated. Sampling temperature and top k or top p sampling can change this behavior.

A model with insufficient training data may memorize specific sequences. Memorization is not necessarily the same as learning generalizable language patterns. Evaluating on unseen text helps distinguish memorization from generalization.

Data augmentation can sometimes increase training diversity. For language data, augmentation should preserve the intended meaning and should not introduce incorrect technical information.

Synthetic training data can be useful when carefully generated and reviewed. However, synthetic data can also amplify errors or repetitive patterns from its source. Quality control is therefore important.

A technical corpus should contain multiple explanations of the same concept using different wording. This exposes the model to variation and can reduce dependence on one exact sentence pattern.

For example, machine learning can be described as learning patterns from data, as optimizing parameters based on examples, or as estimating a mapping from inputs to outputs. Different formulations provide additional linguistic variation.

Python is often used as the orchestration language for machine learning pipelines. A typical pipeline can load data with Pandas, perform numerical processing with NumPy, train a model using scikit-learn or PyTorch, evaluate predictions, and expose the result through an API.

SQL is important in machine learning because training data often comes from relational databases. SQL queries can filter rows, join tables, aggregate records, calculate features, and prepare datasets before they enter a Python pipeline.

A SQL join combines records from multiple tables using related columns. Inner joins return matching records, while left joins preserve all rows from the left table. Group by operations aggregate records according to one or more columns.

Window functions perform calculations across related rows without collapsing the result into a single row. Common window functions include row number, rank, dense rank, lag, lead, and aggregate functions with an over clause.

A common table expression provides a named temporary query result using the WITH clause. CTEs can make complex SQL queries easier to understand and can separate multiple stages of data transformation.

Data engineering supports machine learning by collecting, cleaning, transforming, and delivering data. ETL means extract, transform, and load. ELT generally loads raw data first and performs transformations in the target analytical system.

A data warehouse stores structured data for analytical queries. A data lake can store large amounts of structured, semi structured, and unstructured data. Modern data platforms may combine lake and warehouse capabilities.

Parquet is a columnar storage format commonly used for analytical workloads. Columnar storage can improve query efficiency because systems can read only the columns required for a computation. Parquet also supports compression and typed schemas.

Apache Spark is a distributed data processing framework. PySpark provides a Python interface to Spark. Spark can process datasets larger than the memory of a single machine by distributing computation across multiple workers.

A Spark DataFrame is a distributed collection of data organized into named columns. Spark operations can be transformations or actions. Transformations describe computation while actions trigger execution and return or store results.

Spark uses lazy evaluation for many transformations. Instead of immediately executing every operation, Spark builds a logical plan. Execution begins when an action requires a result.

A Spark partition is a portion of a distributed dataset. Partitions allow work to be processed in parallel. Poor partition sizing can cause inefficient execution or excessive overhead.

A shuffle occurs when data must be redistributed between partitions. Joins, aggregations, and certain transformations can cause shuffles. Shuffles can be expensive because they require data movement.

A broadcast join can be useful when one side of a join is small enough to distribute to worker nodes. Broadcasting can avoid some shuffle operations and improve performance for suitable workloads.

Kafka is a distributed event streaming platform. It can transport streams of records between producers and consumers. Kafka is commonly used in real time data pipelines, event driven systems, and streaming analytics.

A machine learning system can use Kafka to receive events, process them with stream processing, and generate predictions. Real time pipelines require attention to latency, ordering, retries, duplication, and fault tolerance.

MLOps combines machine learning development with software engineering and operations practices. MLOps can include experiment tracking, model versioning, data versioning, automated testing, deployment, monitoring, and retraining.

Model versioning helps teams identify which model produced a particular prediction. Data versioning is also important because changing training data can change model behavior even when the code remains unchanged.

Continuous integration can automatically run tests when code changes. Continuous delivery or deployment can automate packaging and deployment after required checks pass.

A model registry can store metadata about trained models and their lifecycle stages. Production systems may distinguish between development, staging, and production model versions.

Inference latency measures how long a model takes to produce a prediction. Throughput measures how many requests can be processed over a period of time. A production system may need to balance latency, throughput, memory usage, and prediction quality.

Batch inference processes many records together. Online inference processes requests individually or in small groups as they arrive. The appropriate architecture depends on application requirements.

Caching can reduce repeated computation when identical or similar requests occur frequently. However, caching must account for changing model versions and changing external information.

Authentication controls who can access an AI service. Authorization controls what an authenticated user is allowed to do. Production AI APIs should protect sensitive operations and resources.

Logging records important events during application execution. Useful AI service logs can include request identifiers, latency, model version, error types, and system health information while avoiding unnecessary sensitive data.

Security is important when deploying generative AI systems. Applications should consider prompt injection, malicious inputs, data exposure, insecure tool usage, excessive permissions, and abuse of generated content.

Prompt injection occurs when untrusted content attempts to manipulate an AI system into ignoring or overriding its intended instructions. Systems that combine models with tools or retrieved documents should treat external content as untrusted input.

RAG systems can be vulnerable to malicious instructions contained inside retrieved documents. Retrieval pipelines should distinguish data from instructions and use appropriate system-level controls.

An AI agent should receive only the permissions required for its task. Least privilege reduces the impact of an incorrect or malicious action. Sensitive operations may require explicit user confirmation.

Evaluation datasets should contain representative examples of expected user behavior. Edge cases should also be included to test failure modes. Evaluation should be repeatable so that changes can be compared objectively.

A benchmark is useful when its tasks are clearly defined and consistently measured. A benchmark score should not be interpreted without understanding the dataset, metric, model configuration, and evaluation procedure.

Human evaluation can assess qualities that are difficult to capture with simple automatic metrics. Reviewers can evaluate relevance, correctness, clarity, helpfulness, and other criteria according to a defined rubric.

Automated metrics are useful because they can evaluate large numbers of examples consistently. However, no single metric completely captures the quality of a generative model.

Retrieval augmented generation can reduce dependence on information stored inside model parameters. Instead of requiring the model to memorize every document, the system retrieves relevant information at query time.

A RAG query can be processed through several stages. First, the user's question is converted into an embedding. The vector database searches for similar document chunks. Retrieved chunks are combined into a context. The language model receives the question and context and generates an answer.

Hybrid retrieval can combine semantic vector search with keyword search. Semantic search can identify conceptually similar text, while keyword search can perform well for exact names, identifiers, or technical terms.

Reranking can improve retrieval quality by taking an initial set of candidate documents and scoring them with a more sophisticated model. Only the most relevant documents are then passed to the generator.

Context compression can reduce unnecessary information before generation. Removing irrelevant passages can make it easier for the language model to focus on useful evidence.

Grounded generation asks the model to base its response on provided context. Applications can require citations or references to retrieved documents so that users can inspect the supporting evidence.

An embedding model is different from a generative language model. An embedding model converts text into vectors suitable for similarity or classification tasks. A generative language model predicts tokens and produces text.

A vector index organizes embeddings to make similarity search efficient. Exact nearest neighbor search compares a query with every vector, while approximate nearest neighbor methods trade a small amount of exactness for improved search speed.

FAISS supports multiple indexing approaches for vector similarity search. The appropriate index depends on dataset size, dimensionality, memory constraints, and accuracy requirements.

Chunk overlap preserves context across neighboring document chunks. If a sentence spans a chunk boundary, overlap can help ensure that the information appears together in at least one chunk.

Document metadata can include source, title, page number, timestamp, author, or category. Metadata filtering can restrict retrieval to relevant subsets before semantic similarity is calculated.

A chatbot can maintain conversation history to provide context across multiple turns. Long conversations may exceed the model context window, so systems may summarize older messages or selectively retrieve relevant history.

Conversation memory should be designed carefully because irrelevant or incorrect historical information can influence future responses. Applications should define what information is stored and when it is used.

An AI assistant can combine a language model with tools such as search, calculators, databases, code execution, and file retrieval. The language model decides which tool may be useful while the application enforces tool permissions and validates results.

Tool outputs should be treated as data rather than blindly trusted instructions. An agent should validate tool results and handle failures such as timeouts, malformed responses, unavailable services, and unexpected values.

A multi agent system contains multiple specialized AI components that collaborate on a task. One agent may plan, another may retrieve information, and another may review the result. Planning is the process of decomposing a complex task into smaller actions. A planner can identify required steps, dependencies, and expected outputs. Execution then performs the actions and observes their results.

Reflection or critique mechanisms allow an AI system to review an intermediate answer and identify possible errors. Such mechanisms may improve results but also add computational cost and can themselves make incorrect judgments.

A software engineering AI agent can analyze a repository, understand project structure, inspect code, identify errors, propose changes, and run tests. Such an agent requires access to files and development tools in addition to language generation.

The ultimate objective is not simply to obtain a low training loss. A useful model should generalize to unseen examples, produce coherent outputs, and behave consistently on relevant evaluation tasks.

Validation loss is therefore an important metric. A model with extremely low training loss but poor validation loss has learned the training corpus too specifically. Increasing data diversity, applying regularization, reducing model capacity, or using early stopping can improve generalization.

Perplexity summarizes the uncertainty of an autoregressive language model over an evaluation corpus. It is derived from average negative log likelihood. Lower perplexity indicates that the model assigns higher probability to the observed evaluation tokens.

Perplexity depends on tokenization, vocabulary, dataset, and evaluation procedure. Values from different tokenizers or datasets should not automatically be compared as though they were equivalent.

The tokenizer vocabulary affects the number of prediction classes. A model with a larger vocabulary predicts among more possible tokens. A smaller vocabulary may require more tokens to represent the same sentence.

BPE vocabulary size is therefore a tradeoff. A very small vocabulary creates longer sequences, while a very large vocabulary increases embedding and output layer sizes. The appropriate size depends on corpus characteristics and model constraints.

A corpus should contain enough examples for the tokenizer to learn useful subword merges. With a very small corpus, many potential merges may never be observed enough times to provide meaningful compression.

Tokenization statistics can be useful diagnostics. Developers can measure vocabulary size, average tokens per word, sequence length distribution, and frequency of common tokens.

The distribution of token frequencies often follows a long tail. A small number of tokens occur frequently while many tokens occur rarely. This is one reason subword tokenization can be effective.

Data cleaning should preserve meaningful punctuation and sentence boundaries when those signals are useful to the language model. Removing too much punctuation can make generated text less natural.

Whitespace normalization can reduce accidental formatting variation. However, important document structure such as paragraph boundaries should not be removed blindly.

Training examples can be created from continuous token streams. If document boundaries are important, special separator tokens can be inserted between documents. This prevents the model from treating the end of one document as naturally connected to the beginning of another.

A validation split should contain representative content that the model does not see during parameter updates. Random document splitting can work for independent documents, while chronological splitting may be necessary for temporal data.

A fixed random seed makes dataset splitting reproducible. Reproducibility is especially useful when comparing model configurations because changes in validation data can otherwise make metrics difficult to interpret.

A model checkpoint should be saved after training or at regular intervals. Periodic checkpoints protect against interruptions and allow comparison between different training stages.

Checkpoint naming can include experiment identifiers, model configuration, or validation metrics. This makes it easier to identify which model produced a particular generation.

A generation script should restore exactly the tokenizer and model configuration used during training. If the tokenizer merges or vocabulary mapping changes, generated token IDs may no longer correspond to the correct learned embeddings.

The generation prompt should be encoded using the same tokenizer as the training data. The model then predicts a probability distribution for the next token based on the encoded prompt.

Temperature scaling modifies logits before sampling. A temperature below one makes high probability tokens more dominant. A temperature above one makes the probability distribution flatter and increases diversity.

Top k sampling selects only the k highest scoring candidate tokens. This prevents very unlikely tokens from being sampled. However, too small a k can make generation repetitive.

Top p sampling selects a dynamic set of candidates based on cumulative probability. It adapts the number of candidate tokens according to how concentrated the distribution is.

Greedy decoding always chooses the highest probability token. It is deterministic but can produce repetitive text. Sampling introduces variation and can sometimes produce more natural output.

Beam search keeps multiple candidate sequences and can be useful for some sequence generation tasks. For open ended language generation, sampling is commonly preferred because multiple plausible continuations exist.

Repetition penalties modify the probability of tokens that have already appeared. They can reduce repeated phrases, although excessive penalties can distort natural language.

Stopping criteria determine when generation ends. A model can stop after a maximum number of tokens, when an end of sequence token is generated, or when another application-specific condition is satisfied.

A small language model may not have learned an end of sequence token if the tokenizer and training corpus do not explicitly provide one. In that case generation commonly stops using a fixed maximum length.

The current RoshanLM implementation uses a fixed context window and autoregressive token generation. Future versions can add explicit special tokens, better stopping behavior, top p sampling, repetition control, and configurable prompts.

A language model trained from scratch is a useful demonstration of machine learning fundamentals because every prediction depends on learned parameters. The model begins with random weights and gradually adjusts them through optimization.

At initialization, the model has no useful knowledge of Python or machine learning. The training corpus provides examples from which the model learns statistical patterns. The resulting representations emerge through repeated optimization.

The tokenizer itself is not a language model. It performs a deterministic mapping between text and token IDs based on learned vocabulary and merge rules. The neural network learns the statistical relationships among those token IDs.

The embedding layer converts token IDs into vectors. The positional embedding provides information about where each token occurs. The Transformer layers transform these representations based on attention and nonlinear processing.

The final language modeling head converts hidden representations into vocabulary logits. Softmax converts logits into probabilities when probabilities are needed for sampling.

Cross entropy encourages the correct next token to receive high probability. Repeating this objective over many sequences trains the model to predict language patterns.

The model's ability to generate text comes from repeatedly applying the next token prediction function. Each prediction becomes part of the input for the next prediction.

Autoregressive generation can be understood as a loop: encode the prompt, run the model, select a token, append the token, truncate to the context window if necessary, and repeat.

This simple loop is one of the fundamental mechanisms behind text generation in decoder-only Transformer language models.

RoshanLM is a small educational decoder-only transformer designed to demonstrate the main components of a language model. The project uses a custom BPE tokenizer, token embeddings, positional embeddings, causal self attention, multi head attention, feed forward layers, residual connections, layer normalization, cross entropy loss, AdamW optimization, dropout, validation loss, perplexity, checkpointing, and autoregressive generation.

The goal of RoshanLM is not to compete with large language models. The goal is to understand how language modeling works by implementing the important components directly. A good language model project should separate training data from validation data. The tokenizer should normally be trained only on the training corpus to reduce information leakage. The validation corpus should not influence tokenizer merges or model parameter updates. Keeping these datasets separate provides a more meaningful estimate of generalization.

When training a language model, decreasing training loss alone is not sufficient. Validation loss should also be monitored. If training loss continues to decrease while validation loss increases, the model may be overfitting. Early stopping can preserve the checkpoint that achieved the best validation performance.

Model capacity should match the amount of training data. Increasing embedding dimension, attention heads, or transformer layers increases the number of parameters. With a small dataset, excessive capacity can allow memorization. A smaller model with regularization can sometimes generalize better on a small educational corpus.

The relationship between tokens, vocabulary size, context length, and model capacity is important. A larger vocabulary can reduce sequence length but increases the number of output classes. A smaller vocabulary produces longer sequences but gives the model fewer output classes. The best choice depends on the corpus and the available training data.

A custom language model should be evaluated using multiple prompts rather than a single example. Prompts can cover different concepts from the training domain. Generation quality can be evaluated for relevance, grammatical structure, repetition, malformed words, and whether the response remains within the learned domain.

A checkpoint should contain enough information to reconstruct the model. Useful checkpoint metadata includes vocabulary size, context length, embedding dimension, number of attention heads, number of layers, dropout configuration, tokenizer mappings, BPE merges, and model state. Saving this information prevents architecture mismatches during generation.

The training loop should save the best validation checkpoint rather than simply saving the final epoch. A model can continue improving on the training set after validation performance has stopped improving. Keeping the best validation checkpoint provides a safer model for later evaluation.

RoshanLM can be improved through several controlled experiments. Increasing the amount and diversity of training data is one possible improvement. Better tokenization is another. Increasing context length can help the model learn relationships across longer sequences. Increasing model capacity can help when sufficient training data is available.

Every model improvement should be measured using a consistent evaluation procedure. Changing several components at once makes it difficult to identify which change caused an improvement or regression. Controlled experiments should change one major variable at a time whenever possible.

A useful machine learning project is not defined only by its final metric. The engineering process is also important. Dataset preparation, tokenizer design, model implementation, training stability, validation, checkpointing, generation, error analysis, and experiment comparison demonstrate practical understanding of machine learning systems.
